Questão 1

Um desenvolvedor relata que o Datadog Agent dele não consegue enviar metrics porque está atrás de um firewall restritivo. Qual porta de saída (outbound) precisa estar aberta para o Agent se comunicar com o Datadog intake?
Mostrar a resposta e a explicação

Resposta correta

A. 443

Explicação

O Datadog Agent envia todos os dados via HTTPS para as URLs de intake do Datadog pela porta 443. As portas 8125 (DogStatsD) e 8126 (APM) são para tráfego de *entrada* (inbound) no Agent, vindo das aplicações.

Questão 2

Você está fazendo o troubleshooting de uma instalação do Datadog Agent em um servidor Linux. Qual comando mostra o uso atual de recursos (CPU/RAM) do processo do Agent?
Mostrar a resposta e a explicação

Resposta correta

B. `top` ou `htop`

Explicação

`top` ou `htop` mostram o uso de CPU e memória em tempo real por processo, então você consegue encontrar os processos do Agent (como `agent`, `trace-agent` e `process-agent`) e ver o `%CPU` e a memória deles. O `datadog-agent status` informa o estado dos componentes e dos checks do Agent, não uma visão em tempo real da CPU e da RAM do processo. O `datadog-agent info` era um comando do Agent v5 e não existe no Agent v6/v7. O `df -h` mostra o uso de disco por filesystem, não por processo.

Questão 34

Uma metric do tipo Gauge é mais adequada para qual das opções a seguir?
Mostrar a resposta e a explicação

Resposta correta

A. Percentual atual de uso de memória.

Explicação

Um GAUGE registra um instantâneo (snapshot) de um valor em um ponto no tempo, como a leitura de um termômetro. O uso atual de memória é um nível que sobe e desce, então é um gauge. Requests por segundo e erros na última hora contam eventos, portanto são metrics COUNT (ou RATE). O tempo de execução de uma função é um conjunto de medições cuja distribuição importa, então se encaixa em um HISTOGRAM ou DISTRIBUTION.

Questão 35

Sua aplicação chama o `increment` do DogStatsD com o valor 5 e depois 10 dentro do mesmo flush interval de 10 segundos. Qual total o Agent agrega para esse intervalo antes de enviá-lo?
Mostrar a resposta e a explicação

Resposta correta

A. 15

Explicação

O Agent soma todos os valores COUNT recebidos em um flush interval, então agrega 5 + 10 = 15. Observe que um COUNT enviado pelo DogStatsD é armazenado no Datadog como um RATE: cada valor é normalizado por segundo ao longo do flush interval, então um gráfico mostra 15 / 10 s = 1,5. Para ver os totais brutos, aplique uma função como Cumulative Sum ou Integral.

Questão 41

Você quer monitorar o tempo de execução de uma query de banco de dados usando o DogStatsD. Qual tipo de metric é o mais apropriado?
Mostrar a resposta e a explicação

Resposta correta

A. Histogram

Explicação

Um HISTOGRAM (ou um TIMER, que é um histogram para dados de tempo) foi projetado para valores como o tempo de execução de uma query. A partir das amostras de cada flush interval, o Agent calcula `avg`, `median`, `max`, `count` e `95percentile`, para que você veja tanto as queries típicas quanto as lentas. Um GAUGE guarda apenas o último valor do intervalo, então a maioria das amostras se perde. "Increment" é uma operação de COUNT para contar eventos, não para medir durações. Um SET conta valores únicos. Se você precisa de percentis precisos entre muitos hosts, uma DISTRIBUTION também é uma boa escolha.

Questão 45

Qual ferramenta você pode usar para enviar manualmente um pacote UDP para a porta 8125 e testar o DogStatsD?
Mostrar a resposta e a explicação

Resposta correta

D. `nc` (netcat)

Explicação

O DogStatsD escuta na porta UDP 8125, e o `nc -u` (netcat) consegue enviar um datagrama UDP bruto, por exemplo `echo -n "custom.metric.name:1|c" | nc -4u -w1 localhost 8125`. O `telnet` só abre conexões TCP, o `curl` usa protocolos como HTTP sobre TCP e o `ping` envia ICMP echo requests, então nenhum deles consegue enviar um pacote UDP para a porta 8125.
